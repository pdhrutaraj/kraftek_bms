# KRAFTEK BMS — Qt 6 MVC Operator HMI (Revised 0.4)

A Qt 6 Widgets / C++17 desktop HMI prototype with Qt SQL / SQLite3 persistence using the previously selected professional dark navy/graphite industrial UI with restrained teal highlights. The project is revised to match the current product baseline: **48 V nominal lead-acid cranking bank, four 12 V / 180 Ah batteries in series**. The BMS slave itself is displayless; this application represents the separate external HMI/main processor.

## Product baseline represented

- Application: high-current generator engine cranking.
- Bank: 4 × 12 V, 180 Ah lead-acid batteries (VRLA / AGM / flooded) in series; 48 V nominal.
- Telemetry: B1–B4 block voltage at 0.01 V display resolution target, total bank voltage, bank current, four external NTC terminal-lug temperatures, SoC/SoH estimates, sensor/data freshness.
- Cranking design envelope: 600–700 A for 3–5 seconds; bank sag to 36 V during a genuine start should not trip ordinary undervoltage logic.
- Charging baseline: 10–40 A.
- Proposed hardware short-circuit trip criterion: >900 A for >50 ms, subject to coordination and formal verification; this HMI does not implement that protection.
- OTP requirement: temperature threshold in the 45–50 °C range; exact trip/reset thresholds must be approved.
- Interfaces under consideration: RS-485 Modbus RTU or CAN. No live interface is enabled in this prototype.
- SQLite3 runtime storage and a prototype statistical anomaly-diagnostics service are implemented in this revision. They are advisory only; live CAN/RS-485, calibrated coulomb counting, validated SoC/SoH algorithms, and a trained/validated ML model remain future integration work.

## Build on Ubuntu with Qt 6.5.3

```bash
cd kraftek_bms_qt6_mvc
QT_PATH="$HOME/Qt/6.5.3/gcc_64"
cmake -S . -B build_x86 \
  -DCMAKE_PREFIX_PATH="$QT_PATH" \
  -DQt6_DIR="$QT_PATH/lib/cmake/Qt6" \
  -DCMAKE_BUILD_TYPE=Release
cmake --build build_x86 --parallel "$(nproc)"
./build_x86/kraftek_bms
```

Or run `./build_x86_64.sh` (supports `QT_PATH` override).

## Folder layout

- `src/domain/`: typed telemetry structures.
- `src/model/`: Qt table model for B1–B4 readings.
- `src/view/`: overview, battery details, alarms/events, integration status.
- `src/controller/`: MVC coordination.
- `src/services/`: simulated data source and SQLite3 runtime database service.
- `src/ai/`: rolling-baseline statistical anomaly detector (advisory prototype).
- `src/interfaces/`: data-source abstraction.
- `resources/styles/`: professional dark industrial theme.
- `docs/`: system architecture, interface/control matrix, verification plan, open decisions.
- `docs/database_schema.sql`: SQLite schema also created at runtime.
- `docs/ai_ml_design.md`: implemented diagnostic behavior, limits and production validation plan.

## Important limitations

**Simulation only; not for operational control.** Values are generated by `SimulatedDataSource`. No CAN/RS-485 device, current sensor, contactor, charger disconnect, shunt, or protection controller is connected. SQLite stores the simulated samples and advisory events on the external HMI. The statistical diagnostic prototype is not a trained ML model, and its output is not a protection signal. The UI's status text is not proof of physical safety. Do not use it to switch high-current hardware.

Safety protections must be deterministic and local to the BMS/protection hardware, independent of Qt, AI inference, communications, and SQLite availability. AI outputs are advisory only. Do not assume a lithium-only commercial BMS is compatible with this lead-acid application without written manufacturer confirmation.

## Safety-critical decisions still requiring approval

1. Define undervoltage behavior: inhibit/disconnect **discharge/load** to prevent deep discharge, or disconnect charging? These are different functions. Cranking undervoltage must be qualified separately from low resting voltage.
2. Validate no-trip behavior through the full 600–700 A / 3–5 s crank profile and 36 V sag envelope.
3. Coordinate >900 A / >50 ms SCP with sensor response/bandwidth, hardware comparator/latch, fuses, cables, contactor/interrupt device, and battery prospective fault current. Threshold alone does not establish safety.
4. Approve exact per-12 V block and bank OVP/UVP thresholds, OTP trip/reset hysteresis, current direction convention, sensor accuracy, isolation, calibration, and communications-loss state.
5. Decide how the charging path is physically interrupted. Cranking current interruption hardware must be rated for DC fault current and the actual circuit topology.

## SQLite3 runtime behavior

The application creates `kraftek_bms.sqlite3` under Qt's `QStandardPaths::AppDataLocation` for the application. It initializes the schema automatically and writes one telemetry snapshot plus four block-reading rows on each refresh. Diagnostic findings are written to the `events` table when the advisory finding changes. The Qt `QSQLITE` driver/plugin must be present in the Qt 6.5.3 installation. The application continues to be a simulator until a qualified hardware data source replaces `SimulatedDataSource`.
